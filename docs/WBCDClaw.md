这个项目的目标是新做一套移动端优先的网页工作台，服务对象是我自己，主要用于碎片时间完成数据清洗、数据标注、训练配置修改、训练启动和训练状态查看。
系统不承载真机遥操作，也不暴露本地机械臂控制接口。整体定位是“远程数据与训练管理前端”，运行在服务器上，通过手机浏览器经公网访问。
核心价值是把原本必须坐在电脑前完成的管理型工作迁移到手机端完成，同时保留后续扩展到电脑浏览器的能力。

系统形态采用标准 Web 架构。
前端是移动端优先的浏览器页面，后端是服务器上的业务服务，负责数据访问、标注写回、配置管理、训练任务调度、日志读取和状态聚合，训练本体由后端托管的后台任务执行。
前端与后端之间通过明确的业务接口通信，前端只负责展示和提交用户动作，训练命令、文件写入、目录访问、任务启动等动作都由后端受控执行。
系统需要支持公网访问，因此入口层要具备稳定域名或稳定可达地址、鉴权机制和 HTTPS。这里的重点是“稳定入口”，不是单独追求固定 IP。

第一版功能范围收敛为五个能力：样本浏览，样本清洗与标注，常用训练配置编辑，训练任务启动，训练状态与日志查看。
页面数量控制在较少规模，建议为登录页、首页、样本页、配置页、训练页。
首页承担任务入口和状态总览功能，样本页承担连续清洗与标注功能，配置页承担高频参数编辑与模板选择功能，训练页承担任务启动、进度查看、失败排查和历史记录查看功能。
后续如有需要，再加批量操作、高级配置、统计分析和电脑端增强页面。

首页应该强调“快速进入当前工作”，而不是展示复杂大盘。
首页顶部展示当前待处理样本数量、运行中训练数量、最近失败任务数量、最近编辑的配置模板和一个继续上次工作的位置。
页面首屏要能直接进入“继续清洗”和“启动训练”两个高频入口。首页信息密度可以高，但控件数量要可控，手机单手点击区域要足够大，状态标识要清楚，首屏滚动层级要浅。

样本页是第一优先级页面，也是整个系统最关键的页面。
它对应的真实任务是用户在碎片时间快速判断一条样本是否保留、如何打标签、是否需要备注、是否要修 instruction、是否需要调整片段边界。
页面结构建议固定为上中下三段：上方是预览区，中间是样本元信息区，下方是操作区。
预览区展示低成本预览资产，例如关键帧、缩略图、短视频或多视角拼图；
元信息区展示任务名、episode id、视角、时长、来源批次、当前标签、审核状态、备注摘要；
操作区展示高频动作，动作建议直接表面化，例如保留、删除候选、质量低、遮挡、失败演示、边界有问题、instruction 待修、加备注、下一条。
这个页面的设计目标是每条样本在 1 到 3 次点击内完成一次处理。
页面需要支持顺序处理与筛选处理两种模式，顺序处理用于快速过样本，筛选处理用于集中处理某一类问题样本。
为了适配手机，预设标签应尽量做成可直接点选的标签按钮，文本输入只承载备注等低频补充信息。
样本页还需要记录“当前处理进度”和“上次停留位置”，以便用户在碎片时间中断后继续处理。

样本浏览层面，后端应将数据组织成可检索的样本单元，单元粒度建议对齐到用户实际做决策的粒度，可以是一整段 episode，也可以是经过预切分的 clip。
系统需要支持按任务、日期、数据批次、视角、已有标签、审核状态、失败类型等维度筛选。
为了提高移动端效率，列表页展示字段应该克制，首屏只放对判断最有价值的信息，更多细节放到详情页或折叠区。
样本资源访问上，后端需要准备轻量预览资产，手机默认加载轻量版本，点击后再请求更高质量内容。
这样可以保证公网和手机场景下的响应速度。

标注与清洗写回需要具备清晰的数据模型。
每条样本至少包含原始标识信息、当前状态、标签集合、备注、instruction 修订结果、边界修订结果、操作者、修改时间、版本号。
数据层需要保留操作历史，便于回滚和审计。对于“删除”类动作，建议做成软删除或“删除候选”状态，由系统在后续流程中再做统一清理。
这样用户在碎片时间里误触时恢复成本较低。系统还应支持“稍后处理”或“跳过”状态，以便用户在信息不足时先向前推进工作流。

配置页承载训练配置管理，但页面组织方式应围绕高频参数来设计，而不是围绕原始配置文件来设计。
实际实现上建议把配置分为模板层和实例层。模板层是用户常用的训练方案，例如某个任务、某个模型、某个 checkpoint 基线、某组默认超参数；
实例层是在模板基础上的本次运行参数。
配置页首屏展示模板选择和高频参数编辑区，
高频参数建议包括任务名、数据集路径、训练数据过滤条件、输出目录、checkpoint 路径、是否 resume、batch size、learning rate、epoch、LoRA 开关、相机视角、动作维度相关选项、日志命名或运行名。
页面底部再提供一个高级配置入口，用于处理低频复杂参数。这样可以把绝大多数手机上的配置操作压缩到表单式交互里。
后端需要支持配置的保存、克隆、重命名、版本化和最近使用记录，方便用户快速复用。

训练页负责完成“启动一项训练”和“看清一项训练当前状态”两个任务。
训练启动区要支持从模板创建、查看当前关键参数摘要、点击启动、查看资源约束提示。
状态区要展示任务名称、启动时间、当前状态、运行节点或设备信息、最近 loss 摘要、最近 checkpoint、日志尾部和失败信息。
日志展示以最近几十行为主，同时支持展开查看更多。
手机端读取日志的目标是帮助用户快速判断任务是否正常启动、是否已经挂掉、失败原因大致是什么。
训练页还应包含历史任务列表，支持按状态筛选，例如运行中、排队中、失败、完成。
对于失败任务，需要在列表级别就能看到失败摘要，减少用户逐个点开排查的成本。

任务执行层需要与网页请求解耦。
训练启动动作到达后端后，后端创建任务记录并交由后台任务管理器执行，任务管理器负责启动脚本、采集状态、汇总日志、更新进度、处理结束状态。
前端通过轮询或推送机制获取状态。系统需要保证前端断开连接时训练继续执行，前端重新进入后仍可看到完整状态。
任务管理器还需要具备任务并发控制、重复任务命名策略、失败状态落盘和日志路径归档能力。
资源层面建议后端统一维护可用 GPU 状态和当前运行任务数，启动训练前做基础校验，避免误触导致资源挤占。

后端接口设计应围绕业务动作定义，而不是围绕底层文件系统定义。
可以将接口划分为四类：样本接口、标注接口、配置接口、训练接口。
样本接口负责列表、详情、预览资源和筛选；
标注接口负责保存标签、备注、instruction、边界修订和历史记录；
配置接口负责模板读取、实例生成、参数保存和版本管理；
训练接口负责任务启动、状态查询、日志读取和历史检索。
这样可以把前端需要的能力边界收紧，也方便后端做权限控制和输入校验。

数据存储建议分层处理。样本原始数据、预览资源和训练产物保留在文件系统或对象存储中；
任务状态、配置模板、标注记录、操作历史、样本索引保存在轻量数据库中。
数据库层至少需要支持按样本 id、任务名、状态、日期、标签等维度快速查询。
预览资源可以在离线阶段预生成，也可以在首次访问时懒生成并缓存。
为了保证手机端体验，样本页首屏依赖的资源必须轻量且可快速返回。

安全边界需要在第一版就做进去。
系统虽然不接真机控制，但它仍然具备修改数据、修改配置和启动训练的能力.
配置保存采用版本化，训练启动有资源约束，重要操作需要确认。删除类操作有恢复路径，训练启动记录操作者与参数快照，便于后续追踪。
公网入口统一由受控网关转发到后端服务，对外仅开放必要端口。系统中任何“执行命令”“读取路径”“写入文件”的能力都应固化在受控后端逻辑中。

移动端交互风格要以效率为中心。页面信息密度可以高，但要把信息分成“首屏决策信息”和“展开后细节信息”。
常用动作固定在底部操作区，保证单手操作连续性。输入优先选择型控件和标签型控件，减少文本输入。
状态标签保持统一命名和统一颜色语义。列表页支持快速筛选与最近筛选条件保留。
页面切换和返回时保持上下文，例如样本页返回列表后仍停在原位置，训练页返回后仍保留当前筛选。
系统整体要支持竖屏使用，宽屏作为增强模式处理。

工程实现顺序建议按闭环优先。
第一阶段完成用户登录、首页、样本列表、样本详情、基础标注写回和进度恢复；
第二阶段完成配置模板、常用参数编辑和模板保存；
第三阶段完成训练任务启动、状态查询和日志尾部；
第四阶段补充历史任务、失败摘要、样本高级筛选和预览资源优化；
第五阶段再扩展批量操作、统计视图和电脑端增强页面。
整个项目的里程碑以“用户能否在手机上独立完成一次样本清洗”和“用户能否在手机上独立启动并确认一次训练是否正常运行”为核心验收标准。
